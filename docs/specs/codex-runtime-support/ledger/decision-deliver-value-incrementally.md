# Deliver a usable Codex workflow before expanding platform certification

Anton accepted the council recommendation: “yeah, I want to prioritize the results and value and we could always do incremental improvements later”. Build the Codex adapter and a normal execute → handoff workflow next, using native facilities and the existing signed-in environment when installation testing is authorized.

Close Phase 1 on completed characterization, normalized values, bounded discovery, controlled lifecycle and explicit capability limits. Its old-writer cutover proof moves to Phase 2's mixed-write activation gate; positive native hook execution/trust moves to Phase 4's hook activation gate. Neither missing proof becomes a pass. Build and fixture-test adapters before requiring installed-host acceptance, and keep unproved capabilities disabled.

Support one proved configuration first. Preserve Claude behavior and protect live/unknown ownership. Native limitations still require a concrete activation decision; a new marker cannot constrain old code. Custom retention stays deferred. No profile manager, installer, global bridge, live install, copied auth, trust bypass, push or release is authorized by this re-plan.
