## Findings that change the plan

1. **babysit.md is missing from the files list, and without it 2.5 is wrong.** babysit.md:9-11 picks the
   mode `hold` word → spec `ship:` → auto. An approved PR on a `ship: hold-for-review` spec launched
   "in auto mode" (2.5) would be held a second time. babysit.md must say an approved PR is auto.
2. **A second version pin.** `T/tests/board-command.test.ts:35` pins `board.version` as the literal `1`;
   the phase lists only the golden. Bumping `BOARD_VERSION` (`T/board/model.ts:7`) breaks it; read
   the constant there instead.
3. **The gh exit-code guidance is already met.** `toArray` (`T/pr/gh-lists.ts:26-31`) checks `code === 0`
   before parsing; nothing to add beyond the new fields.
4. **`CHANGES_REQUESTED` outlives the fix.** GitHub keeps the decision until the reviewer reviews again,
   so the `pr-changes` row stays after the relaunched worker pushes. oversee-crew.md must relaunch once
   per review (key: the newest review's id/time), never once per wake.
5. **`nextFromChecks` (`T/board/joins.ts:93`) stops being about checks only** once review state drives
   it; rename it to say what it decides (`prNext`).
