# Phase 3 preflight — In-flight overlay (items 1–5)

Inputs: phase entry, `research/phase-3/2026-10-01-1-5-recon.md`, `principles.md`, `technical.md` →
*Activity*, *Lanes*, *Joins*, *Rank*. Paths relative to `skills/spec/tools/`.

## Findings that change the plan

1. **"Every reason is a needs on a phase ticked in one workspace" can't be read from `readySet`.**
   Reasons are strings (`ready/ready-set.ts:5-8, 44-65`), and `needs deployed …` shares the `needs `
   prefix. Instead: for each workspace with ticks in the spec, rerun `readySet` on a copy of the base
   state whose phases ticked there are marked done. A waiting phase that becomes ready in exactly one
   such copy is ready in that workspace. `needs-deployed` stays unmet (ticked ≠ deployed), and base
   `states`/`nodes` are never touched (`decision-branch-ticks-never-satisfy-needs-from-main`). Scope:
   same-spec needs; a cross-spec need met only on a branch stays blocked.
2. **`joins.ts` has nothing to join in phase 3.** Its three joins (`technical.md` *Joins*) are
   workspace → spec (claims first: phase 5), session → row and PR → row (phase 4). Workspace → spec
   from `WorkspaceScan.specs` is what `phaseActivity` already does. Drop `joins.ts` and
   `board-joins.test.ts` from this phase; phase 4 creates them.
3. **In flight can't be "every base phase not done, checked for activity".** A spec whose base has no
   `progress.md` (stage `create`) can have ticked phases on a branch, and those phases aren't on base.
   Build the in-flight lane from the activity map (every key with `tickedIn` or `wipIn`, phase not done
   on base, spec not paused or finished on base), then drop those keys from ready and blocked.
4. **`SpecState.inFlight` is taken** (`core/spec-state.ts:25-30`, the text of `in-flight.md`). Name the
   new inputs `workspaces: WorkspaceView[]`, not anything `inFlight`.
5. **`◀ here` and `main checkout` need board-level facts.** `workspaceCell` renders `basename(path)`
   (`board/cells.ts:44-46`); the board has no current path and no main-checkout path. Add `here` and
   `mainCheckout` to `Board` (data, not text); render marks the matching workspace. Without sessions
   (phase 4), a wip row's next is `executing`; phase 4 refines it from sessions and PRs.
