# Installed-candidate local-cycle acceptance

Agent-operated driver for the restricted pilot. Run when the selected candidate is already installed through authorized native operations and the exclusive separate clone is explicitly assigned. Use [native-entry.md](native-entry.md), [capabilities.md](capabilities.md) and canonical modes. Anton does not run shell setup or maintenance scripts. This driver does not install, change profiles, launch sessions, claim, publish or clean up worktrees.

## Evidence and stop conditions

Record evidence in the owning spec's `research/phase-<id>/YYYY-MM-DD-installed-local-cycle.md`, then retain pending state in its existing in-flight file. A source checkout, copied package, synthetic socket/CLI/ID, direct native shell command or catalog observation proves only its bounded behavior. None passes installed model acceptance. Native gates require both real sessions below.

Inputs: actual installed SKILL.md path; independently intended candidate content revision; explicit pilot checkout, original managed checkout, spec, exact phase and one bounded real code chunk. Missing input or bootstrap refusal stops acceptance. Do not establish eligibility through legacy placement, ID aliases or claims. Preserve configured model/permissions, home and native trust.

Before work, record both checkouts' `git rev-parse --path-format=absolute --git-common-dir`, `git worktree list --porcelain`, canonical roots and baseline HEAD/status. Require different common directories, one pilot checkout, and absence of the pilot from the original clone's worktree list. Retain the passing frozen `runtime-legacy-readers` clone-isolation scenario, including its linked-worktree positive control and source hashes. That scenario executes historical discovery only in disposable repositories. Never run historical removal on real work. No marker substitutes for the common-directory boundary.

## First real model session

1. Resolve the actually loaded installed candidate root and run its `codex.ts --assets`. Compare root/content revision with the intended candidate. Record exact root, revision, version, supported CLI/API configuration, original request and actual initiating native ID/cwd from successful bootstrap. Catalog version alone is insufficient. Another loaded session in the clone or stored ownership stops acceptance without changing that state.
2. Bootstrap explicit `execute <spec> <phase>` through that entry. Require `Workflow: local-pilot`. Read canonical execute, stable references and scoped ledger; run recon/preflight before code. Do actual model work on a useful code chunk of this port.
3. Through the same entry/options, invoke `-- lessons recall <project-relative-file…>` before edits. Retain output, including an honest no-match. Read matching rules. Recall newly touched paths before each later edit group.
4. Exercise invalid-edit feedback in one new owned temporary ledger entry: write a heading without frontmatter; invoke `-- doctor <spec> --file ledger/gotcha-local-cycle-validation.md`. Retain the existing checker's error. Correct kind/applies-to/created/body and rerun the same command to a clean result. Obtain created from the existing timestamp helper. Index it only if it captures a durable lesson; otherwise remove this owned probe before commit. Do not damage an existing entry or commit invalid state.
5. Complete the real chunk and run focused tests/typecheck/required checks. After every spec edit invoke `-- doctor <spec> --file <spec-relative-file>`, correct errors/new warnings and run `-- doctor <spec>` before local commits. Retain actual output; no trusted native hook is claimed.
6. Follow update through that entry, retaining actual `update` request. Use `-- phase tick <spec> <phase> <item-prefix>` only for implemented items. Check phase/progress, code-map and scoped ledger. Keep native acceptance and other unfinished deliverables open.
7. Bootstrap actual `handoff`, then follow canonical local handoff: reflection, ledger, current in-flight, doctor and local commit. Record commit/clean status. Do not append handoff history to progress or tick PR gates because this procedure exists.
8. Report **Local restricted handoff complete** and **Ownership, remote publication, cleanup and next-session launch unavailable**. Native hooks/full managed parity remain pending. End this session's use of the clone. Do not launch its successor through unready tooling or keep both sessions loaded there.

## Fresh real model session

The independently started successor receives only installed candidate/expected revision, explicit roots/spec/phase, committed handoff hash and actual request `resume <spec> <phase>`. Do not forward the previous conversation as pickup context.

1. Repeat installed asset inspection/bootstrap. Require intended root/content revision, same isolated checkout, no stored claims, a different actual native ID, complete source evidence and no prior loaded session occupying the clone. A new shell process or invented environment ID is not a fresh model session.
2. Verify HEAD equals committed handoff and status is clean. Read resume's persisted phase/progress/in-flight; retain Stage A's confirmation halt. Do not execute the next chunk automatically.
3. After normal confirmation, read selected stable references, code-map and scoped ledger. State what changed, checks passed, remaining work and next bounded action from committed files. Keep the actual request as resume.
4. Record fresh-session evidence and verdict locally. Missing/mismatched observations remain pending or failed. Do not infer publication, ownership release, cleanup, native hooks or managed handoff.

## Retained evidence

| Observation | Required record |
|---|---|
| Provenance | Actual installed root/content revision in both sessions; intended revision; supported CLI/API |
| Isolation | Roots, distinct common dirs, worktree enumeration, historical scenario and positive control |
| Real work | Model session IDs, requests/cwd, useful code diff/commits, recon/preflight and checks |
| Feedback | Recall before edits; invalid-file error, correction/clean rerun; final doctor |
| Handoff | Phase/progress/ledger/code-map/in-flight, local commit/status, unavailable-action report |
| Pickup | Different real ID, same candidate/committed HEAD, persisted context, Stage A halt/confirmed Stage B |
| Limits | Source fixtures separately labelled; native hooks, managed actions and full parity still pending |

If only deterministic fixtures ran, record source evidence and leave installed acceptance pending. Full parity remains required by this port's workflow-parity.md.
